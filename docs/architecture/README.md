# Architecture Decision Records

This directory holds **decisions**, not history. An ADR exists to stop a settled
question from being re-litigated, and to tell a future contributor which
alternatives were already rejected and why. If a document's bulk is "what we
changed", it belongs somewhere else.

## The test

> Does this record a **choice that constrains future work**, together with the
> alternatives that were rejected?

Apply it before writing an ADR and before promoting a plan:

| The content is… | It belongs in |
|---|---|
| A choice between designs, with trade-offs accepted | **An ADR here** |
| What was fixed, shipped, or renamed, in order | [`CHANGELOG.md`](https://github.com/benolabsai/benostreamdb/blob/main/CHANGELOG.md) |
| A post-mortem: symptom → root cause → fix → regression test | The `Fixed` section of the changelog, or `docs/governance/` if it is a standing operational hazard |
| Work that is not finished | `plans/` |
| A user-facing contract (how to call it) | `docs/*.md` (published as guides) |
| How a module is structured for a reader | code comments and the module docs |

A promotion is a rewrite, not a `git mv`. Moving a plan into this directory
without reshaping it produces a fix ledger with an ADR filename.

## Required shape

Every ADR opens with a status block and then uses these sections, in this order:

```markdown
# ADR-NNN: <the decision, as a claim>

> **Status: proposed | accepted | superseded by ADR-NNN (`vX.Y.Z`).**
> Implemented across <the handful of modules that matter>.
> Change history: [`CHANGELOG.md`](https://github.com/benolabsai/benostreamdb/blob/main/CHANGELOG.md).

## 1. Context
The forces in play. Why the status quo was no longer tenable. State the cost of
getting it wrong in operational terms (data loss, an unreadable table, an
unshippable release) — not in adjectives.

## 2. Decision
Numbered decisions (D1, D2, …). Each one names the alternative that was
**rejected** and why. A decision with no rejected alternative is probably not a
decision — it is an implementation note.

## 3. Consequences
Positive outcomes, then the negative ones that are accepted anyway, then the
**risk the decision takes on**. Be explicit about what gets worse.

## 4. How the decision is enforced
The tests, CI gates, or invariants that fail if someone violates it. An ADR with
no enforcement is a wish. Include the revisit triggers: the conditions under
which this record should be superseded.
```

Sections 1–4 are the minimum. A "What shipped" section is acceptable only as a
short pointer to the changelog; if it outgrows §2 and §3, the document is a fix
log.

## Conventions

- **Numbering is append-only.** Numbers are never reused, even after a record is
  superseded. The filename is `ADR_NNN_SHORT_DESCRIPTIVE_TITLE.md` — the
  docname `guides/adr_NNN` that [`index.rst`](https://github.com/benolabsai/benostreamdb/blob/main/docs/source/index.rst) references is
  generated by [`scripts/prepare_docs.sh`](https://github.com/benolabsai/benostreamdb/blob/main/scripts/prepare_docs.sh).
- **Accepted records are immutable.** Corrections go in a new ADR that
  supersedes the old one; the old one keeps its original text with
  `Status: superseded by ADR-NNN`.
- **"Decided" is not "implemented".** A record may be `proposed` while a plan is
  live, but it must not be `accepted` until the enforcement in §4 exists.
- **No marketing.** Numbers, mechanisms, and trade-offs.

Three documents that had been numbered as ADRs were deleted in `v0.16.0` because
they were not decisions: a graph-RAG feature set with a post-mortem, a binding
ergonomics fix list, and a partitioned-indexing fix list. Their surviving content
is in [`CHANGELOG.md`](https://github.com/benolabsai/benostreamdb/blob/main/CHANGELOG.md).
Deleting them is the reason the series could be renumbered contiguously.
